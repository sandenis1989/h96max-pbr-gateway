# Архитектурное ТЗ: PBR-шлюз с нуля

## Целевая среда
- Целевой хост: `root@192.168.0.102` (доступ по SSH-ключу настроен).
- Перед любыми изменениями сначала подключиться по SSH, собрать факты об архитектуре CPU (`uname -m`), ОС (`/etc/os-release`), сетевых интерфейсах (`ip -br a`) и активном фаерволе (`nftables` / `iptables`).

## Требуемая архитектура (3 контура маршрутизации)
1. **Прямой маршрут (bypass):** российские IP-диапазоны (`russian_ips` / `bypass_vpn`) идут напрямую через локальный шлюз провайдера без VPN и DPI-обхода.
2. **DPI-обход:** трафик YouTube и целевых доменов обрабатывается локально через `zapret` (`nfqws`).
3. **Зарубежный трафик:** весь остальной трафик направляется через Hysteria 2 (без обфускации Salamander, с конфигом подключения к VPS в Осло) с использованием `TPROXY` (порт 7893) / `REDIRECT` (порт 7892) и policy-based routing (`fwmark 0x1` -> таблица маршрутизации `100`).
4. **Сервисы и персистентность:**
   - `dnsmasq` — локальный DNS с автонаполнением наборов IP/доменов для маршрутизации;
   - `tailscale` — в режиме exit node;
   - `systemd`-юниты для сохранения и автоматического восстановления правил фаервола, наборов IP и `ip rule` после перезагрузки.

## Инженерные правила работы
- Использовать скиллы `superpowers`: сначала исследование и план, затем пошаговая реализация и проверка каждого шага.
- Все скрипты, конфиги и юниты сначала создавать локально в этом Git-репозитории с понятными коммитами, а затем деплоить на `192.168.0.102`.
- Секреты (адрес/пароль VPS для Hysteria 2, ключи Tailscale) не хардкодить в репозитории — использовать шаблон `.env.example` и игнорируемый `.env`.
- После каждого этапа проверять результат живыми диагностическими командами на хосте (`ip rule`, `nft list ruleset` / `iptables-save`, `dig`, `curl`).
